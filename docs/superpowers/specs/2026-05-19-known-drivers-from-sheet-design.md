# Список валидных водителей из листа «Пробіг» — Design

**Дата:** 2026-05-19

## Проблема

Список валидных водителей для учёта пробега захардкожен в `parser.py` как
константа `KNOWN_DRIVERS` (строки 58–61). Сообщение о пробеге от водителя не из
этого списка молча игнорируется (`parser.py:212`).

Чтобы добавить нового водителя (например, при подключении нового города), нужно
править код `parser.py` и делать редеплой. Это неудобно: добавление водителя —
операционная задача, а не задача разработки.

При этом константа дублирует уже существующий источник: лист «Пробіг» (колонка
`B4:B300`) — CLAUDE.md прямо называет его «источником правды о водителях», а
`sheets.py` → `_upsert_mileage_impl` уже отклоняет водителей не из листа
(`driver_row is None → return False`).

## Цель

Список валидных водителей берётся из листа «Пробіг» (колонка B). Добавление
водителя = добавление строки в таблицу, без правок кода и редеплоя. Константа
`KNOWN_DRIVERS` удаляется.

## Объём

**В объёме:** вынос `KNOWN_DRIVERS` из кода в лист «Пробіг».

**Вне объёма:** словарь `DRIVER_ALIASES` остаётся в коде как редкий escape-hatch
для имён, которые автотранслитерация рус→укр приводит к канонической форме
неверно. Большинство имён нормализуются автоматически, поэтому правка
`DRIVER_ALIASES` — редкая операция, её вынос не оправдан (YAGNI).

## Архитектура

Источник правды — колонка B листа «Пробіг» (`B4:B300`), уже читается методом
`_get_driver_rows()` с кэшем TTL 1 час.

Парсер остаётся **чистым** модулем без обращений к Google API. Список валидных
водителей **приходит параметром** в `parse()` — парсер сам в таблицу не ходит.

### Поток данных

```
лист «Пробіг» B4:B300
      │
      ▼
_get_driver_rows()  [кэш per-instance, TTL 1 час]
      │
      ▼
SheetsManager.get_mileage_drivers() -> set[str]
      │
      ▼
bot.py:  known = sheets_manager.get_mileage_drivers()
         parser.parse(text, known)
      │
      ▼
parser.py:  if name in known_drivers:  → событие EVENT_MILEAGE
```

## Компоненты

### `parser.py`

- Удалить константу `KNOWN_DRIVERS` (строки 58–61).
- Сигнатура: `parse(self, text, known_drivers=frozenset())`. Дефолт `frozenset()`
  — вызов без параметра безопасен: события пробега просто не создаются, падения
  нет.
- Строка 212: `if name in self.KNOWN_DRIVERS:` → `if name in known_drivers:`.
- Self-тест в `if __name__ == "__main__"`: текущий список `test_messages` не
  содержит кейсов пробега и вызывает `parse(msg)` с одним аргументом — благодаря
  дефолту `frozenset()` вызов остаётся валидным без правок. Добавить 1–2 кейса
  пробега с локальным тестовым множеством водителей, чтобы покрыть новый
  параметр.

### `sheets.py`

- Новый публичный метод `get_mileage_drivers(self) -> set`:
  `return set(self._get_driver_rows().keys())`.
- Переиспользует существующий кэш `_get_driver_rows()` (TTL 1 час) — отдельного
  кэша не нужно.

### `bot.py`

- Точка вызова парсера (строка ~338, `events = parser.parse(text)`):
  получить список водителей и передать в парсер:
  ```python
  known = sheets_manager.get_mileage_drivers()
  events = parser.parse(text, known)
  ```

## Обработка ошибок и крайние случаи

- **Лист недоступен** (`mileage_sheet is None`): `_get_driver_rows()` возвращает
  `{}` → `get_mileage_drivers()` возвращает пустое множество → события пробега не
  создаются. Мягкая деградация — тот же режим отказа, что и сегодня в
  `upsert_mileage`.
- **Задержка кэша:** после добавления водителя в лист бот примет его в течение
  ≤1 часа (TTL кэша), либо сразу после рестарта. Строго лучше текущего поведения
  (правка кода + редеплой). Команду принудительного обновления кэша не вводим
  (YAGNI).
- **Заглушки-водители** («Водитель1/2/3» в харьковском блоке): формально станут
  «валидными», пока висят в листе. Безвредно — сообщений о пробеге от водителя с
  таким именем не бывает.
- **Совпадение имён:** в листе хранятся канонические украинские формы,
  `normalize_driver_name()` приводит входящее имя к той же форме,
  `_get_driver_rows()` уже делает `.strip()`. Дополнительная нормализация не
  нужна.

## Тестирование

- `python parser.py` — self-тест: добавить 1–2 кейса пробега (например
  «Косич 120 км») с локальным тестовым множеством водителей, передаваемым в
  `parse()`. Существующие кейсы (без пробега) продолжают работать с дефолтным
  `frozenset()`.
- Ручная проверка после деплоя:
  - известный водитель пишет «Имя 120 км» → пробег записывается;
  - «Сегодня проехали 200 км» → события пробега нет;
  - добавить строку в лист «Пробіг», рестарт бота → новый водитель пишется.
- Юнит-тесты `core.py` (`tests/test_core.py`) этим изменением не затрагиваются.

## Поведение

Поведение бота для конечного пользователя не меняется: пробег по-прежнему
пишется только для водителей из листа «Пробіг». Меняется лишь происхождение
списка — из захардкоженной константы в динамически читаемую колонку B.
